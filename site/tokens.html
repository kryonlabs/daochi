Protocol Mesh Apps Tokens API

Tokens

Signed Waozi receipts for official app purchases and spends.

Daochi can issue waozi:token receipts after verifying Google Play, Monero, or admin credits. The ledger is append-only, account-scoped, and app-tagged.

Ledger model

Every token event records issuer, asset, account, optional app_id, event type, amount delta, ledger sequence, previous hash, event hash, signature, source type, and source reference. Official clients verify the Ed25519 issuer key and accept only issuer_id=waozi with asset_id=waozi:token for official Waozi balances.

Purchases credit the account ledger. Spends debit the account ledger and require an app ID plus an idempotency key, so repeating a spend request returns the existing receipt instead of double-charging the account.

IssuerGET /api/v1/tokens/issuer
ProductsGET /api/v1/tokens/products
BalanceGET /api/v1/tokens/balance
LedgerGET /api/v1/tokens/ledger?since=<seq>
SpendPOST /api/v1/tokens/spend

App scoping

Token purchases, spends, invoices, receipts, and spend nonces carry app_id. Daochi validates that the app is registered before accepting a spend or purchase flow. This gives auditability by app and allows clients to prove which app initiated a token event.

The current balance endpoint is account-wide for waozi:token; it is not yet a separate per-app allocation pool. If product policy requires per-app token distribution, the next protocol step should add app-filtered balances, app-filtered ledger queries, and explicit account-to-app allocation events.

Token ledger and payment intent rows are financial audit records. They are scoped by account for balance and receipt lookup, but they are intentionally not included in normal account data export and are not deleted by account-data cascade.
